# v0.4.0-rc.1 Discord Changelog

Short-form announcement. The full changelog is `CHANGELOG.md` at the repository
root, which is also what the release page shows.

---

**unity-asset-reference-mcp v0.4.0-rc.1 — release candidate**

An asset dependency graph is easier to reason about when you can look at it, so
this release adds an interactive viewer, and makes indexing meaningfully faster
on large projects.

**Try it:**
```
npm install -g unity-asset-reference-mcp@next
cd /path/to/UnityProject
unity-asset-reference-mcp-web
```
`latest` still points at 0.3.2, so nothing changes until you opt in.

**New — a graph you can actually see**
The web viewer now renders your dependency graph in 2D or 3D. It highlights what
needs attention (broken references, unused assets, most-referenced assets), and
filters by asset type and origin, with a node budget so big projects stay
navigable.

**New — the viewer starts itself**
Run it from anywhere inside a Unity project and it finds the project root, like
`git` does. It also picks its own free port, so you can have several projects
open at once without configuring anything.

**Faster indexing**
Scanning and reference extraction now run in parallel; database writes stay
serialized so the result is unchanged. A full index at concurrency 1 and 8
produces byte-identical tables. Tune it with `--concurrency <n>` — on a
32,000-asset project, 32 was measurably faster than the default.

**Smaller install**
Roughly 134 MB of downloaded packages became about 40 MB, and the published
package shrank by half. Nothing was removed from the tool; the viewer's build
dependencies simply never needed to be on your machine.

**Unity package downloads**
The Editor exporter is now on the release page as `.tgz`, `.zip`, and
`.unitypackage`, alongside the git URL. The server-less WASM viewer is a
download too, rather than living inside every npm install.

**Heads-up for MCP users**
`search_assets` now matches an asset's name, path, or GUID prefix — it used to
match only the name, so the same query returns more results than in 0.3.2. The
tool list is otherwise unchanged.

**Also fixed**
Starting a second viewer no longer crashes with a port error, `--concurrency`
now reports a bad value instead of ignoring it, and the installers no longer
print a `npm bin -g` hint that stopped working in npm 9.
